# EduTutor — План доработки до production-ready качества

> **Цель документа**: сформулировать конкретные требования к доработке проекта EduTutor,
> чтобы превратить его из MVP в инструмент, который не стыдно показать. Документ адресован
> кодинговому агенту-исполнителю.

---

## Диагностика: что сейчас не так

На скриншотах видно типичную сессию: ученик Артём, 7 класс, Литература, тема «Поэты серебряного века».
Сгенерированный урок содержит:

| Проблема | Пример со скриншота |
|---|---|
| **Мусор из веб-источника просочился в секцию** | «Часть 1: Настоящий материал опубликован пользователем Гарипова Екатерина Юрьевна.» |
| **Определение — одно пустое предложение** | «Поэты серебряного века создали грандиозный поэтический капитал.» |
| **Секции — голые стихотворные фрагменты без анализа** | Часть 2/3 — цитаты стихов без контекста, без заголовков, без разбора |
| **Итог — штамп** | «Поэзия Серебряного века открывает нам неповторимый мир красоты и гармонии.» |
| **Ключевые термины не показаны** | Хотя JSON-схема их поддерживает |
| **Диаграмма не видна** | Не генерируется или не рендерится |
| **Все темы в графе — OKF 50%** | Нет дифференциации мастерства |

## Блок 1 · Качество генерации урока (КРИТИЧНО)

> [!CAUTION]
> Это главная боль проекта. Урок — ключевой продукт, который видит ученик. Сейчас он не информативен.

### 1.1 Увеличить контекстное окно для урока

**Файл**: `src/tutor.py`, константа `MAX_EXPLANATION_CHARS`

Сейчас `MAX_EXPLANATION_CHARS = 2500` — контекст обрезается до 2500 символов. Для литературы
(стихи + анализ + биографии) это критически мало — LLM получает обрывки и генерирует штампы.

```diff
- MAX_EXPLANATION_CHARS = 2500
+ MAX_EXPLANATION_CHARS = 6000
```

Для промпта урока (`_lesson_prompt`) использовать отдельную константу `MAX_LESSON_CONTEXT_CHARS = 8000`,
а `MAX_EXPLANATION_CHARS` оставить для квиз-вопросов.

### 1.2 Усилить фильтрацию мусора ДО передачи в LLM

**Файл**: `src/tutor.py`, функция `_lesson_prompt` (строка ~507)

Сейчас контекст передаётся в LLM «как есть»:
```python
ctx = "\n---\n".join(context)[:MAX_EXPLANATION_CHARS]
```

Нужно:
1. Применять `_clean_text_lines()` к каждому чанку ПЕРЕД конкатенацией
2. Дополнительно фильтровать `_is_publication_metadata()` построчно
3. Удалять строки короче 20 символов без пунктуации (обрывки навигации)

```python
from .knowledge import _clean_text_lines, _is_publication_metadata

def _prepare_lesson_context(context: List[str]) -> List[str]:
    """Очистка RAG-контекста от мусора ПЕРЕД передачей в LLM."""
    cleaned = []
    for block in context:
        lines = _clean_text_lines(block).splitlines()
        lines = [ln for ln in lines
                 if ln.strip()
                 and not _is_publication_metadata(ln)
                 and (len(ln) >= 20 or ln.rstrip("…\"»")[-1:] in (".", "!", "?"))]
        text = "\n".join(lines).strip()
        if text and len(text) >= 40:
            cleaned.append(text)
    return cleaned
```

### 1.3 Усилить промпт: требовать содержательные секции

**Файл**: `src/tutor.py`, функция `_lesson_prompt`

Текущий промпт недостаточно жёстко требует содержательных секций. Добавить:

```
- Каждая секция ОБЯЗАНА иметь:
  1. heading — НЕ "Часть N", а содержательный заголовок ("Символизм: основные черты", "А.А. Блок: поэт и эпоха")
  2. body — минимум 3 предложения СВОИМИ СЛОВАМИ, не копируя контекст дословно
  3. Если цитируешь стихотворение — СНАЧАЛА контекст (кто автор, о чём), ЗАТЕМ цитата в «кавычках», ЗАТЕМ анализ (1-2 предложения: какой приём, что значит)
- definition — минимум 3-4 предложения. Включи: что это за период, когда был, основные черты, главные имена
- ЗАПРЕЩЕНО: секции из одного предложения, секции без heading, копирование метаданных авторов публикаций
```

### 1.4 Валидация секций после генерации

**Файл**: `src/tutor.py`, функция `_lesson_from_data`

Добавить постпроцессинг:
- Секции без `heading` → авто-заголовок `f"Раздел {i+1}"` (лучше чем ничего, но см. 1.3)
- Секции с `body`, содержащим `_is_publication_metadata()` → удалить
- Секции с `body` короче 50 символов → удалить (одно предложение — не секция)
- `definition` с `_is_publication_metadata()` → очистить и пересинтезировать

### 1.5 Fallback-генерация: синтез из контекста

**Файл**: `src/tutor.py`, функция `_synthesize_lesson_from_context`

Текущий fallback берёт предложения ≥55 символов — это слишком коротко для связных секций.
Поднять до 80+ символов. Группировать предложения по смыслу (по общим словам), а не механически по 140 символов.

## Блок 2 · Фильтрация веб-источников (КРИТИЧНО)

### 2.1 Ужесточить фильтр `_is_publication_metadata`

**Файл**: `src/knowledge.py`, `_PUB_METADATA_RE`

На скриншоте в секцию урока просочилось:
> «Настоящий материал опубликован пользователем Гарипова Екатерина Юрьевна.»

Хотя паттерн `материал\s+опубликован` есть в regex, он не сработал — вероятно, из-за строки
`настоящий материал опубликован` (lowercase match). Проверить и добавить:

```python
# Расширить паттерн:
r"|опубликован[аоы]?\s+пользовател"
r"|размещен[аоы]?\s+пользовател"
r"|опубликован[аоы]?\s+на\s+сайте"
```

### 2.2 Применять фильтрацию на уровне чанков при индексации

**Файл**: `src/knowledge.py`, функция `_make_chunks`

Сейчас `_is_web_noise` проверяет строки, но чанк может содержать мусорные строки ВНУТРИ
абзаца (concatenated). Добавить построчную фильтрацию внутри каждого параграфа:

```python
# В цикле создания чанков, ПЕРЕД добавлением:
lines = [ln for ln in p.splitlines()
         if ln.strip() and not _is_web_noise(ln) and not _is_publication_metadata(ln)]
p_clean = "\n".join(lines).strip()
if not p_clean or len(p_clean) < 30:
    continue
```

### 2.3 Поднять приоритет качественных источников

**Файл**: `src/source_finder.py`

Сейчас `_AVOIDED_DOMAINS` опускает порталы учителей в конец, но они всё равно используются,
если лучших нет. Добавить **жёсткий** режим: если есть хотя бы 2 результата из
`_PREFERRED_DOMAINS`, полностью исключить `_AVOIDED_DOMAINS`:

```python
def search_web(...):
    results = sorted(results, key=_rank_source)
    preferred = [r for r in results if _rank_source(r) == 0]
    if len(preferred) >= 2:
        results = [r for r in results if _rank_source(r) < 4]
    return results
```

## Блок 3 · Кэширование и повторное прохождение темы (ВАЖНО)

> [!IMPORTANT]
> Пользователь просил: при повторном прохождении — показать кэшированные материалы, а не искать заново.

### 3.1 Кэширование сгенерированного урока

**Файлы**: `src/graph.py`, `src/states.py`

Сейчас кэшируются только **сырые тексты источников** (по URL в `SOURCES_CACHE_DIR`).
Сгенерированный урок (Lesson JSON) НЕ кэшируется — при повторном прохождении LLM генерирует заново.

**Решение**: кэшировать `Lesson` (JSON) по ключу `(student_id, subject, topic, grade)`:

```python
# В graph.py, после успешной генерации урока (content_node / agent_tutor_node):
_cache_lesson(st, lesson, deps.settings.SOURCES_CACHE_DIR)

# При повторном входе (reuse_gate / content_node):
cached_lesson = _load_cached_lesson(st, deps.settings.SOURCES_CACHE_DIR)
if cached_lesson:
    st.set_lesson(cached_lesson)
    st.lesson_done = True
    _emit(deps, "tutor.lesson", **st.lesson_payload(topic))
    # Спросить: "Показываю урок из прошлого раза. Хочешь дополнить материал?"
```

### 3.2 Изменить UX при повторном прохождении

### 3.3 Кэшировать граф знаний по теме

**Файл**: `src/knowledge_graph.py`

Граф знаний (узлы/связи по учебнику) тоже нужно кэшировать по `(student_id, source_hash)`.

## Блок 7 · Кэш и повторное прохождение (по запросу пользователя)

> [!IMPORTANT]
> Ученик повторно проходит урок с той же темой → показать закэшированные материалы, а не искать сразу.

### 7.1 Архитектура кэша уроков

Создать модуль `src/lesson_cache.py`:

```python
"""Кэш сгенерированных уроков по ключу (student_id, subject, topic, grade)."""

import json, hashlib
from pathlib import Path
from typing import Optional
from api.schemas import Lesson

def _cache_key(student_id: str, subject: str, topic: str, grade: str) -> str:
    raw = f"{student_id}::{subject}::{topic}::{grade}".lower()
    return hashlib.sha256(raw.encode()).hexdigest()[:24]

def save_lesson(cache_dir: Path, student_id: str, subject: str,
                topic: str, grade: str, lesson: Lesson) -> None:
    cache_dir.mkdir(parents=True, exist_ok=True)
    key = _cache_key(student_id, subject, topic, grade)
    path = cache_dir / f"lesson_{key}.json"
    path.write_text(lesson.model_dump_json(indent=2), encoding="utf-8")

def load_lesson(cache_dir: Path, student_id: str, subject: str,
                topic: str, grade: str) -> Optional[Lesson]:
    key = _cache_key(student_id, subject, topic, grade)
    path = cache_dir / f"lesson_{key}.json"
    if not path.exists():
        return None
    try:
        return Lesson.model_validate_json(path.read_text(encoding="utf-8"))
    except Exception:
        return None
```

### 7.2 Интеграция в граф

**Файл**: `src/graph.py`, узлы `content_node` и `agent_tutor_node`

Перед вызовом `generate_lesson()`:

```python
from .lesson_cache import load_lesson, save_lesson

cached = load_lesson(deps.settings.SOURCES_CACHE_DIR / "lessons",
                     st.student_id or "", st.subject or "", topic, st.grade or "")
if cached:
    st.set_lesson(cached)
    st.lesson_done = True
    _emit(deps, "tutor.lesson", **st.lesson_payload(topic))
    _emit(deps, "system",
          message="Показываю урок из прошлого раза. Хочешь дополнить материал?",
          kind="lesson.cached")
    return st.model_dump()

# ... генерация нового урока ...
# После успешной генерации:
save_lesson(deps.settings.SOURCES_CACHE_DIR / "lessons",
            st.student_id or "", st.subject or "", topic, st.grade or "", lesson)
```
