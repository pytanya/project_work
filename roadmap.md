# Дорожная карта: будущие улучшения EduTutor

## 1. Qdrant в Docker вместо in-memory VectorStore

**Цель:** Persistent vector search, масштабируемость, metadata-фильтрация.

**Статус: ✅ Адаптер реализован и протестирован (2026-08-18).** Код готов;
для server-режима нужен Docker (`docker compose up -d qdrant`). Разработка и
тесты работают в embedded-режиме `qdrant-client` (`QDRANT_PATH` — локальный
персистентный каталог), Docker для локального прогона не обязателен.

**Что сделано:**
- [x] `src/qdrant_store.py` — `QdrantStore` с тем же интерфейсом `VectorStore`
  (add/search/count/reset/delete); два режима: server (`QDRANT_URL`) и embedded
  (`QDRANT_PATH`)
- [x] Payload-поля: `subject`, `grade`, `section_number`, `section_title`,
      `source`, `page_number` — metadata-filtered search (конвертация в Qdrant `Filter`)
- [x] Миграция: при старте проверяется коллекция, создаётся если нет;
      имя коллекции включает размерность эмбеддинга (`edututor_1024`/`edututor_384`)
- [x] Переключение через `.env`: `VECTOR_STORE=qdrant` (+ `QDRANT_URL`/`QDRANT_PATH`)
- [x] `docker-compose.yml` (qdrant port 6333/6334; backend; frontend)
- [x] Тесты `tests/test_qdrant_store.py` (add/search/filter/persistence/reset/delete,
      factory `make_store`/`make_qdrant_store`) — embedded-режим, без Docker

**Архитектура:**
```
docker-compose.yml
├── qdrant (port 6333)
├── backend (FastAPI)
└── frontend (Vite dev)
```

**Открытое:** проверка на реальном Qdrant-сервере в Docker на машине с Docker.

## 2. Wiki-LLM (Karpathy-стиль) + OKF persistent knowledge

**Идея:** Агент не просто проверяет знания, а **накапливает** их между сессиями. Каждый учебник, каждая сессия → пополняет wiki-базу знаний (OKF-бандлы).

**Статус: 🟡 Значительная часть реализована (2026-08-18).**

**Компоненты:**
- [x] **Knowledge Wiki** — markdown-файлы с YAML frontmatter (OKF v0.2), организованные по предметам/темам (`src/wiki.py`, `data/knowledge_wiki/<subject>/<topic>.md`)
- [x] **Накопление между сессиями** — статьи персистентны; mastery/attempts/правильные ответы/заметки об ошибках сохраняются
- [x] **Идемпотентность** — `apply_record` (текущий ответ) из `evaluate_answer_node`; `sync_mastery` (без attempts++) из `summary_node`; повторные вызовы не дублируют счётчики
- [x] **API** — `GET /api/wiki`, `/api/wiki/{subject}`, `/api/wiki/{subject}/{topic}`
- [x] **UI** — панель «База знаний» (предмет → темы, цвет = уровень мастерства)
- [x] **OKF auto-export** — при завершении квиза → бандл знаний + mastery scores (`emit_okf_bundle`)
- [x] **Session persistence (SQLite)** — сессии сохраняются между запусками
- [ ] **Wiki-LLM** — LLM-агент, который:
  - [ ] При индексации нового учебника: извлекает факты → пишет/обновляет wiki-статьи
  - [ ] При оценке ответа: сверяет с wiki (а не только с RAG-чанками)
  - [ ] При ошибке ученика: обновляет статью пояснениями (сейчас — rule-based заметки из feedback)

**Формат wiki-статьи (OKF):**
```yaml
---
okf_version: "0.2"
type: Topic
title: "Атмосфера Земли"
topic: "Атмосфера Земли"
subject: "География"
grade: "6"
mastery: 0.85
accuracy: 0.83
attempts: 6
correct: 5
last_studied: "2026-08-17"
notes:
  - "2026-08-17: Ошибка в строении атмосферы"
relations:
  - target: "Климат"
    type: "prerequisite"
---
# Атмосфера Земли
Атмосфера — газовая оболочка Земли...
```

**Открытое (следующий шаг п.2):** Wiki-LLM — LLM-извлечение фактов в статьи при
индексации учебника и сверка ответов с wiki. Уже сделано: `enrich_body` генерирует
тело статьи из RAG-контекста при первом ответе по теме (llm_call, `deps.tutor_llm`).

**Статус: ✅ Значительная часть реализована (2026-08-18) без внешней библиотеки**
(zoom/pan/drag и цвета реализованы на чистом SVG — стабильнее и проще в тестах).

**Что сделано:**

- [x] **Типы рёбер** — `part_of`/`prerequisite`/`related` разными цветами
      (`#64DFDF`/`#FFB703`/`#B388FF`) + легенда
- [x] **Mastery overlay** — цвет узла = уровень усвоения из Knowledge Wiki
      (зелёный ≥0.75 / жёлтый ≥0.45 / красный); API `/graph` возвращает
      `mastery`/`attempts` для узлов; точка-индикатор на узле

- [x] **Онтология** — верхний уровень: книга → страницы-источники → подтемы
      (для веб-графа); учебник → параграфы/уроки (для PDF)

на очень больших графах; drill-down до ключевых понятий внутри темы.

## 5. Агентность: agent_loop + function calling (критично для требований курса)

**Статус:** 🟡 Фаза 0 завершена (багфиксы + инструменты), Фазы 1–2 впереди.

**Проблема:** система выродилась в детерминированный FSM — LLM используется только как
функция «JSON→JSON», а не как агент. `TOOL_FUNCTIONS`/`execute_tool` (`src/tools.py`) —
мёртвый код: function calling не подключён к графу. Известные дефекты:
дублирование вопросов квиза (нет памяти о заданных вопросах в промпте),
невидимый урок/разбор (событие `tutor.lesson` не проходило валидацию `WsEvent`),
«мёртвые» режимы `explain`/`deep_dive` (нет веток в `route_after_topic_gate`).

**Цель (спека 2.3):** гибрид — детерминированная FSM для инфраструктуры
(source/OCR/индексация/экспорт) + единый агентный узел `agent_loop`, где LLM через
function calling вызывает инструменты (интервью, retrieval, урок/квиз/объяснение/глубокий
разбор) и сам решает, продолжать или завершить.

**Фазы:**
- [x] **0. Багфиксы FSM + инструменты** — антидубликат вопросов (7.3.2), видимость урока (7.3.3), ветки explain/deep_dive (7.3.4); слой `src/agent_tools.py` (11 инструментов + TOOL_SCHEMAS); `extract_intake_fields`; переработанный чек-лист
- [x] **1. Пропуск topic-gate при конкретной теме** — после индексации конкретная тема (≠ «все») не переспрашивается: web-материалы → сразу к уроку/квизу; учебник → авто-выбор урока из графа (гейт остаётся для «все»/несовпадения)
- [x] **2. Разговорный intake** — `extract_intake_fields` подключён в `intake_node`: один развёрнутый ответ заполняет несколько полей разом («я в 7 классе, география, тема Атмосфера, учебника нет, хочу квиз» → весь чек-лист + сразу квиз); «все»/«нет» сегментами распознаются
- [x] **3. Подтверждение намерения** — перед поиском/индексацией агент сообщает «Готовлю урок по теме „Бессознательное“…»
- [x] **4. agent_loop для intake** — `src/agent_loop.py`: ReAct-цикл, модель ведёт интервью через `interview_progress`/`set_intake`/`extract_intake_fields`/`route_to_source`; фолбэк на детерминированный `intake_node` при недоступности агентной LLM (в тестах с Callable-моками)
- [x] **5. Подключение TOOL_SCHEMAS** к `LLMClient.chat(tools=...)` — агентный intake вызывает модель с tools и обрабатывает `tool_calls`
- [x] **6. Агент в квизе (опция `USE_AGENT_TUTOR`)** — `src/evaluation.py` (единая логика оценки для узла и инструмента), инструменты `evaluate_answer`/`generate_quiz`/`explain_error`/`deep_dive`/`finish_session`, `agent_tutor_node` + ReAct-цикл `run_tutor_agent`; по умолчанию выключен (детерминированный квиз быстрее: ход агента ~60с из-за 2-3 LLM-вызовов)
- [ ] **7. Наблюдаемость** — логирование `action`/`reason_summary`/`status` по каждому инструменту (10.2)
