## 2. Требования к поведению (чек-лист R1–R37)

### Глобальное / сессия
- **R1.** При открытии при незавершённой сессии: спиннер «Восстанавливаем сессию…»,
  затем ре-гидратация сообщений, состояний квиз-карт, приложенных изображений и
  AI-разборов. Поля ввода disabled до завершения.
- **R2.** Индикатор соединения WS: зелёная точка «онлайн» / серая
  «переподключение…» / красная «офлайн»; клик по красной — тултип «Проверьте подключение».
- **R3.** Каждая длинная задача имеет id и состояние (pending/running/done/error)
  и не блокирует весь UI, кроме случаев, где это технически необходимо (R8).

### Интейк-визард
- **R4.** Визард из 3 шагов «Цель → Материалы → План урока», степпер с номерами и
  галочками. «Далее» disabled, пока тема/цель пусты.
- **R5.** Шаг «Материалы»: список источников с чекбоксами `aria-pressed`;
  недоступные — disabled с пометкой; ошибка загрузки — инлайн-предупреждение,
  но «Далее» активна.
- **R6.** «Сгенерировать план» → спиннер «Составляем план…»; модалка закрывается
  по Esc/клику вне **только когда не busy**; ошибка — инлайн-карточка + «Повторить».
- **R7.** План урока — редактируемый черновик (переименовать/скрыть/переставить)
  **до** создания. «Начать обучение» disabled, пока невалиден; сохранение →
  спиннер «Создаём…» → закрытие + фокус возвращается к инициатору.

### Генерация урока / индексация (long ops)
- **R8.** Генерация урока: не-блокирующий баннер с прогрессом (`progressPhase`) +
  прогресс-бар + текст этапа; кнопка «Отмена» (ход сохраняется частично).
- **R9.** Загрузка/индексация: отдельный `uploadBusy` на карточке файла
  (спиннер + «Индексируется…» + %), пофайловая отмена; загрузка **не** блокирует
  чат; ошибка одного файла не отменяет остальные (пометка + «Удалить»).
- **R10.** Задача > 30 c: счётчик «идёт уже ~45 c» и каждые ~15 c слабое
  «дыхание» индикатора; таймаут — не молча: «Долго не отвечаем, попробуйте ещё
  раз» + «Повторить», контекст сохранён.

### Чат / сообщения
- **R11.** Отправка: текст сразу пузырём (оптимистично), поле очищается, поле+
  кнопка disabled, анимация «печатает»; повторный сабмит невозможен при `chatBusy`.
- **R12.** Стриминг токенов in-place в последний пузырь; авто-скролл по «якорю»:
  если юзер листал вверх — не дёргать; во время стриминга — кнопка «Стоп».
- **R13.** У ответа ассистента меню «Повторить / Изменить / Удалить»; сломанный
  JSON-ответ → мягкая авто-ре-генерация без UI-молчания.
- **R14.** Suggested-next-question подтягивается после завершения хода в
  placeholder; Tab — принять, Enter — отправить; медленный запрос не ломает композер.

### Квиз-карты
- **R15.** Квиз — карточки с чипами 1..N и прогресс-баром; авто-проверяемые чипы
  окрашиваются зелёным/красным, открытые — галочкой.
- **R16.** Поле ответа по типу (кнопки/T-F/input/textarea/textarea-mono). «Проверить»
  disabled до ввода; для открытых — приложить изображение (фото решения).
- **R17.** Сабмит: опции блокируются, мгновенный бейдж «Верно/Неверно»
  (авто-проверяемые) + подсветка опций; открытые — «Эталонный ответ» + «AI-разбор»,
  без автоматической красной отметки.
- **R18.** После сабмита: «Повторить» (сброс выбора, сохраняет вложения),
  «AI-разбор» (стриминговый, индикатор «Оцениваем…», при ошибке — «Не удалось
  оценить»), сворачиваемая «Правильный ответ/Объяснение», «В банк вопросов».
- **R19.** Состояние ответов и разборов персистентно; reload восстанавливает
  карточки; результаты на бэкенд — по завершении всех вопросов (best-effort + retry).
- **R20.** «Follow-up» у вопроса — отдельная панель чата с закреплённым контекстом,
  бейдж-счётчик новых сообщений.

### Ошибки / подсказки
- **R21.** Неверный ответ: «Подсказка» (ур.1) → «Подсказка 2» (ур.2) →
  «Показать объяснение»; каждое нажатие логируется; после сабмита подсказка disabled.
- **R22.** Открытые ответы — после отправки приглашение «Объясни, как ты пришёл
  к этому ответу» (Socratic, через Follow-up/AI-разбор без готового ответа).

### Панели (Wiki, KG, «Мои знания», источники)
- **R23.** Wiki (донат): обновляется после ответов; 0% — подсказка «Прогресс
  появится, когда ты ответишь на вопросы»; клик по сегменту — подсветка связанных карточек.
- **R24.** Knowledge Graph: zoom/pan/drag (есть); клавиатурная навигация (Tab/стрелки,
  +/−); empty-state «Загрузи материалы» + кнопка «Загрузить».
- **R25.** «Мои знания»: узлы с состоянием; переход в «освоено» — короткая анимация
  (минимальная конфетти, уважает `prefers-reduced-motion`).
- **R26.** Whitelist-панель: скелетон-плейсхолдеры при загрузке; пусто — «Нет
  источников» + CTA; недоступный источник disabled с пояснением.

### Сеть / WS
- **R27.** Потеря WS: типинг очищается, баннер «Соединение потеряно,
  переподключаемся…» с прогрессом ретраев; кнопка отправки disabled; при
  восстановлении — синк состояния, отправленное «в пустоту» помечается и переотправляется.

### Ошибки системы
- **R28.** Исчерпан бюджет/нет ключа: не блокировать UI — инлайн-баннер «Бюджет
  исчерпан» + «Настроить».
- **R29.** Не найдены материалы: плашка «По материалам ничего не нашёл — ответил
  из общих знаний» + чип «Реши уточнить по источникам» + предложение загрузить файлы.
- **R30.** Сбой генерации: красная карточка с текстом + «Повторить»/«Изменить
  запрос»; история сохраняется.

### Пустые состояния
- **R31.** Первый запуск: герой «О чём хочешь узнать?» + поле + чипы-подсказки.
- **R32.** Новая сессия без сообщений: «Следующая тема» + 3 стартер-кнопки
  (быстрая проверка / объясни интуитивно / сложный вопрос), disabled при загрузке.

### Доступность
- **R33.** Опции квиза — реальные `<button>`/`<input>` с `aria-pressed`;
  стрелки + Enter; фокус не уходит из карточки.
- **R34.** Модалки: `role=dialog`, `aria-modal`, фокус-trap, начальный фокус,
  возврат фокуса, Esc-закрытие.
- **R35.** Стриминг/типинг: live-region `aria-live=polite` «Ассистент печатает».
- **R36.** Цвет — не единственный сигнал: везде дублируем иконкой/текстом (✓/✗).
- **R37.** Анимации уважают `prefers-reduced-motion`.

## 3. Приоритеты

**MVP (must-have):** R2, R3 (минимальный: id задачи для длинных операций), R8–R10
(в варианте «один не-блокирующий баннер + отмена между шагами», без пофайловой
отмены и частичного сохранения — см. 4a), R11–R13, R15–R19 (R19 = гидратация фида,
не изменение бэкенд-момента), R21, R27–R32, R33–R37. R1 и R4–R7 — только после
бэкенд-resume/визард-задач (roadmap #9/#10) или вынести из MVP.

**Nice-to-have:** R14 (suggested-next-question), R20 (Follow-up), R22 (Socratic),
R23–R26 (связь панелей, конфетти-мастерство), пофайловая отмена + частичное
сохранение (см. 4a), полная модель фоновых задач с pause/resume (R3 full),
оценка стоимости до генерации (из DeepTutor).

## 4. Сверка с текущей реализацией (что уже есть)

- Стриминг токенов (`token`), typing-индикатор, `chatBusy`/`uploadBusy`, баннер
  прогресса индексации, `system.heartbeat`, reconnect с backoff, `quickAnswer`
  toggle, «База знаний» (mastery-полосы), граф-«Созвездие» (Canvas) с drill-down,
  панель «Мои знания», «Повторить (N)», hint/review-пузыри — **есть**
  (roadmap #1–8, Фаза 1–2).
- **Доступность модалок — частично:** `TopicModal.jsx:47` уже имеет
  `role="dialog"`+`aria-modal`, Esc-закрытие (`TopicModal.jsx:30-33`). Нет
  focus-trap и начального/возвратного фокуса → R34 = «частично», не «отсутствует».
- **Отсутствует/слабые места:** индикатор WS-соединения (R2), Stop-кнопка
  стриминга (R12), «Повторить/Изменить/Удалить» у ответа (R13), фронтенд-гидратация
  состояния квиз-карт при reload (R19), suggested-next-question (R14), live-region
  при стриминге (R35), focus-trap (R34), Socratic-приглашение (R22),
  Follow-up-чат (R20).

## 4a. Зависимости от бэкенда (по результатам критики, 2026-09-01)

Вердикт: 🟡 доработать. Структура хорошая, но несколько MVP-пунктов зависят от
несделанного бэкенда или противоречат текущей архитектуре. Уточнения:

- **R1** («Восстанавливаем сессию…») — нет resume-эндпоинта (фронт всегда создаёт
  новую сессию: `App.jsx:557-579`; `restore_or_create` — мёртвый код). Зависит от
  roadmap #9 (resume-механизм). Или вынести из MVP.
- **R19** — переписать на **per-answer персистенцию**: оценка и синк уже идут
  после каждого ответа (`evaluate_and_record`, `src/evaluation.py:98`; синк Student
  KG/wiki/review после каждого ответа). «Отправить по завершении всех вопросов»
  сломает мгновенную обратную связь (R17/R18). R19 = фронтенд-гидратация фида из
  `GET /session`/истории, без изменения бэкенд-момента отправки.
- **R8/R9/R12 (отмена)** — cancel кооперативен (`engine.py:553-555`), состояние
  сохраняется только после шага, upload — один файл (`api/routes/documents.py:25-61`).
  «Частичное сохранение»/«пофайловая отмена»/«Стоп стриминга» = новая бэкенд-работа
  (cancel-token + прерывание in-flight + обработка orphan-потоков). В MVP оставить
  только отмену между шагами; «пофайловую отмену» и «частичное сохранение» — в
  nice-to-have.
- **R4–R7 (визард 3 шага)** — текущий intake — чек-лист + кнопки
  (`IntakeWizard.jsx:27-58`), визарда нет. Добавить в gap-список roadmap #10
  задачи по `IntakeWizard`/`IntakeCard` либо понизить до nice-to-have.
- **R3 (модель задач)** — предпосылка для R8/R9: перенести минимальный вариант
  (id задачи для длинных операций) в MVP, иначе R8/R9 нереализуемы честно.
- **R29** — свернуть с бэкендом: сейчас при провале поиска — `content.empty`/
  `source.failed` + предложение включить источники, узел «ответ из общих знаний»
  не подтверждён (`graph.py:1835` ставит `failed`). Перед реализацией зафиксировать
  бэкенд-поведение или пометить R29 как новый бэкенд-узел.
- **R10 (таймаут)** — контракт: WS-событие `step.timeout` (status=interrupted) →
  UI-карточка с «Повторить» → POST /message с сохранённым текстом; тест на переотправку.
- **R36** (дублирование цвета иконками) — дешёвый a11y-фикс, сочетается с R33/R35
  (MVP) → перенести в MVP, а не в nice-to-have.
- **Критерий приёмки:** по каждому R из MVP добавить тест в
  `frontend/src/__tests__/` (пример: `App.test.jsx:57,81-83` уже проверяет рендер
  опций/кнопки «Отправить» — правки R13/R33 аддитивны, риск низкий).
